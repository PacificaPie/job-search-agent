# career-archive — 经历捕获(捕获层)

把本人在项目里实际做的事,如实、迭代地记进一个独立的私有 git 数据仓。写一次、长期沉淀,后续简历/面试都从这里取。

本 skill 只管**捕获**:原原本本记"做了什么"。按方向裁剪措辞/格式是**另一个** skill(resume-tailor,后续做)的事,别在这里做。

## 数据仓位置(代码 / 数据分离)

数据**不**存在本 skill 包里(包会被整包替换、可能只读)。存到外部本地私有 git 仓,默认路径:

```
~/career-archive/
├── projects/<项目名>/WORKLOG.md   ← 每个项目一份,如实迭代
└── archive.md                      ← 跨项目的全局提炼库
```

- `<项目名>` 取当前项目目录名。
- 若该路径不存在 → 说明还没配数据仓,先按下方"首次配置"引导本人建好,别把内容瞎写到别处。

## 捕获什么 / 不捕获什么

**捕获(这些是本人的,带得走、写简历也安全):**
- 用过的技术、方法、工具、框架
- 关键判断、权衡、为什么这么选
- 踩的坑、怎么解决的
- 认知 / 思路怎么一步步迭代的
- 本人在其中的具体贡献(界定边界,不夸大)
- 结果与学到的东西(可对外表述的层面)

**不捕获(这些是公司的,任何通道都不该带出——出事反咬的是本人,公司不兜底):**
- 源码、专有实现的具体细节
- 内部 / 未公开数据、未获准对外披露的指标
- 内部文档原文
- 客户 / 个人数据
- 任何会违反保密义务的内容

起草时:可以去看项目里的 commit、改动文件、本次 session 的工作来**还原**本人做了什么;但**写出来的是贡献级摘要**,用本人的口吻、泛化到可移植且不泄密的程度——不是把 proprietary 内容抄进去。

## 捕获工作流(/capture)

0. **开工先同步(必须,防止在旧副本上写)**:进数据仓先把远端最新拉下来,再动笔。
   ```bash
   cd ~/career-archive && git pull --rebase
   ```
   - 这是捕获层唯一需要的"读"动作——只为拿到最新的 WORKLOG,避免在过期副本上 append、push 时冲突或覆盖。
   - 若 `git pull` 报认证错误:提示本人去本机配一次认证(见"commit & push"),**不要**尝试输入或索要 token。
   - 若有本地未提交改动导致 rebase 失败:停下来告诉本人,别强推、别丢改动。
1. 读当前项目的近期工作(本人的 commit、改动、本次 session 干的活)。
2. 起草一条 WORKLOG 条目(schema 见下),只写"捕获什么"里那些,主动剔除"不捕获"那些。
3. **审核闸(必须,不可跳过)**:把草稿给本人看,明确请其确认两件事——
   - ① 准确:是否真实反映了本人做的事
   - ② 可对外:有没有混进保密内容
   只有本人**明确同意**后才进下一步。
4. 追加进 `~/career-archive/projects/<项目名>/WORKLOG.md`(追加,不覆盖已有)。
5. commit & push(见下)。
6. (适时)把值得进简历的事实从 WORKLOG 蒸馏进 `~/career-archive/archive.md`。

## WORKLOG 条目 schema

```
### YYYY-MM-DD 标题
- 做了什么: 本人的具体贡献(界定边界)
- 用的技术 / 方法:
- 关键判断与权衡: 为什么这么做
- 踩的坑 / 怎么解决:
- 认知迭代: 思路怎么变的
- 结果 / 学到: 可对外表述的层面;无硬指标就写过程性描述,不编
```

## commit & push

审核通过后(开工时已 `git pull --rebase` 同步过远端,这里直接提交即可):

```bash
cd ~/career-archive
git add -A
git commit -m "capture: <项目名> <一句话>"
git push
```

- 自动 push 的前提是本机已配好 git 对远端的认证(`gh auth login` 或 SSH key)。本 skill 只调 git,**不碰、不索取任何凭证**。
- 若 push 报认证错误:提示本人去本机配一次认证,**不要**尝试输入或索要 token。
- 网页 App 这类沙盒里没有本人的文件系统和凭证,本 skill 跑不了捕获 + push;它的运行环境是 **Claude Code / Cowork**。

## 首次配置(数据仓还不存在时引导本人执行)

在本人**自己的设备、个人 git 账号**下,执行一次:
1. 建私有仓:GitHub 上建一个 **private** 仓后 clone 到默认路径,或本地 `git init ~/career-archive`。
2. 配 git 认证以便自动 push:`gh auth login`(或配 SSH key)。
3. 建好结构:`mkdir -p ~/career-archive/projects && touch ~/career-archive/archive.md`。
4. 之后"一调用就捕获"即可。

## 铁律

- 只记本人的贡献与思考,不搬公司原始内容。理由是**保护本人**:保密岔子只会反咬本人,公司不兜底。
- 不编造指标;机密数字用相对 / 定性表达。
- 审核闸不可跳过——它既防失真,也防把不该带的东西 push 出去。
